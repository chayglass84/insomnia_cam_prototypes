# INS-2793 — Simplify environment picking & configuration

## Problem

Picking and configuring environments is too complicated to discover today. This is a **UX-only** change: no behavior changes to how environments actually work (scoping, inheritance, sync, private vs shared) — only how they're presented and how discoverable configuration actions are.

## Background (current behavior, unchanged)

- **Project-level environments**: stored as hidden `scope: 'environment'` workspaces at the project level, usable by any collection in the project. Each can itself have shared/private sub-environments.
- **Collection-level environments**: stored inside the collection (workspace), usable anywhere in that collection. Has a base environment + shared/private sub-environments.
- **Folder-level**: not a real "environment" — a `RequestGroup` has an `environment`/`kvPairData` field edited via an "Environment" tab in the folder pane. **Out of scope for this task.**
- Inheritance: collection overrides folder overrides project (existing behavior, unchanged).
- Sub-environments: "shared" (`isPrivate: false`, synced/exported) vs "private" (`isPrivate: true`, never synced/exported).
- Secret env vars / raw-JSON vs table (KV) toggle: exists today (`EnvironmentKvPairDataType.SECRET`, `useToggleEnvironmentType`). **Out of scope for this task.**

## Current implementation (for reference)

- `packages/insomnia/src/ui/components/environment-picker.tsx` — `EnvironmentPicker`. Single button in `workspace-pane-header.tsx` opens a popover containing: a "Project Environments" panel (a searchable `ComboBox` to pick *which* project-level file, then a separate `ListBox` below it to pick a specific sub-environment within that file — two nested pickers) and a "Collection Environments" panel (one flat `ListBox` of base + sub-environments).
- `packages/insomnia/src/ui/components/modals/workspace-environments-edit-modal.tsx` — `WorkspaceEnvironmentsEditModal`, the full editor opened via the collection panel's edit icon. Has a hidden-until-hover "+" icon next to the base environment row that opens a menu with "Shared environment" / "Private environment" — this is the low-discoverability add flow being fixed.

## What's changing (this task)

1. **Project-level dropdown**: collapse the current two-level picker (search combobox → sub-environment list) into **one flattened dropdown** listing every project environment file with its sub-environments nested/indented underneath. One tooltip on the section explaining scope. Each **top-level file row** gets its own edit icon that navigates to that file's environment route (`/organization/:orgId/project/:projectId/workspace/:workspaceId/environment`) — same navigation the current gear button uses, just per-row instead of only for the currently-selected file.
2. **Collection-level dropdown**: keep the existing flat base+sub-environment list; add a tooltip explaining scope. Single edit icon next to the dropdown (not per-row) opens `WorkspaceEnvironmentsEditModal`, same as today.
3. **Popover/trigger structure**: unchanged — still one trigger button in the header opening a popover; only the *contents* of the popover are simplified per above.
4. **`WorkspaceEnvironmentsEditModal` discoverability**: replace the hidden hover-only "+" icon/menu with two explicit, always-visible buttons: **"Add Sub Environment"** and **"Add Private Sub Environment"**. Same underlying create action as today (`isPrivate: false` / `true`), just surfaced directly instead of hidden behind a menu.

## Explicitly out of scope

- Folder-level "Environment" tab (request group state).
- Secret environment variables / raw-JSON vs table (KV) toggle.
- Any change to inheritance, sync, or storage behavior.
- Moving the tab-bar navigation model (edit-as-tab keeps using existing full-page route navigation, not real tab-bar integration).
