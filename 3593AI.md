## The three jobs (what the branch is for)

1. **Debug / discover one endpoint** — work item 1 (chat window) and 5 (policies tab). Works against any URL.
2. **Test prompts across models** — work items 2, 3, 4, 6, 7, 8 (sync, Model Evaluator, cost, judge, scoring, prompts project). Work item 10 covers how all three jobs are made discoverable.
3. **Test whether a skill helps a model** — work item 9 (skills), evaluated through 3.

Layout agreed 2026-10-13: the **gateway project** is the source of truth for routes and models (one flat `Routes and Models` folder); a second **local prompts project** (Git later) holds `Prompts` and `Skills` folders and is tied to one gateway.

**Two projects, named explicitly (2026-10-16):** **`Models for <gateway>`** (Konnect is the source of truth; its collection shows one tab, **Models & Pricing**; no evaluator, judge or scoring) and **`Testing for <gateway>`** (local, Git later; its collection tabs are **Evaluate** (a sentence and an "Open Model Evaluator" button), **Judge** and **Model Scoring**). Judge and scoring settings therefore live only on the testing project. The sync sets the gateway project's name on every run; the testing project is found by its marker, or adopted by its name.

Vocabulary: **route = path**. Several models can share a path and are told apart by the body `model` value (`opus`, `fable`). Never show Konnect's *display name* in the UI (user preference): show the alias and the actual model.

## 1. Chat window for LLM traffic (Oct 1–5)

**What:** chat-completion responses (OpenAI / Anthropic / Gemini shapes) render as chat bubbles with markdown; a model + token summary bar; streaming (SSE) requests get a live **Chat** tab with follow-ups; non-streaming request bodies get a structured **Chat / Raw** compose editor.

- **Bubbles** (`common/chat-completion.ts`, `viewers/response-chat-viewer.tsx`): shape detector that folds the request's prior turns in; falls through to the normal editor when the JSON isn't a chat shape. The old click-to-expand inspector was removed once content rendered as markdown.
- **Streaming Chat tab** lives in `websockets/realtime-response-pane.tsx` (streaming requests render `RealtimeResponsePane`, never `ResponsePane`; earlier work in the wrong file was dead code). Token-by-token fill via `useStreamSummary`; `extractStreamChatMeta` reads model/usage/stop reason from chunks. `inferStreamSummaryPath` matches with `endsWith` so gateway-prefixed paths (`/anthropic/v1/messages`) work.
- **Compose editor** (`common/chat-request.ts`, `editors/body/chat-request-editor.tsx`): serializes by merging into the existing body so unknown fields survive. Hidden for event-stream requests (Raw editor instead).
- **Settings bar** (`viewers/chat-settings-bar.tsx`): editable model (dropdown with a per-format suggestion list, free text allowed; inside a gateway workspace it suggests the route's model values), system prompt, temperature, max tokens; warns "reconnect to use them" and Reconnect uses the just-applied body.
- **Streaming UX:** teaser banner offers "Enable streaming" (one click fixes header + body flag and auto-connects, via `ui/utils/pending-auto-connect.ts`); a banner offers `"stream": true` when only the header is set; Enter sends follow-ups; **Save as Default Body** (only typed user messages) and **Clear Chat Window** buttons; chat history is local state, not persisted to the request.
- **Totals and cost:** every reply shows `model / N tokens in, M out / $cost`; header shows conversation totals (`common/chat-totals.ts`). Earlier replies' usage lives in an in-memory cache (`chat-turn-meta-cache.ts`), lost on reload. OpenAI-format streams report **no usage** unless the body has `stream_options.include_usage: true`, so a banner offers to add it.
- **Verified:** 11 Playwright smoke tests in `insomnia-smoke-test/tests/smoke/ai-chat-streaming-response-pane.test.ts` (mock SSE server on the existing smoke server) passed when written; not re-run since later work. Unit tests: `chat-completion`, `chat-request`, `chat-streaming`, `stream-summary`.
- **Open:** **To check later:** the non-streaming Chat compose editor flickered while typing (visual only, last seen 2026-10-05; Cam doesn't remember whether it still does; a real fix needs a React-profiler pass); Gemini prior turns don't show as bubbles; Gemini has no settings-bar sampling fields; stream usage extraction depends on the chunk shapes actually seen.

## 2. AI Gateway sync + catalog (Oct 6, reshaped Oct 13/14)

**What:** the same Konnect **Sync** button also pulls AI Gateways. Each gateway becomes a project with a model catalog and a ready-made request tree.

- **Sync** (`konnect/sync.ts` `syncAiGateways`): `GET /v1/ai-gateways`, then `/v1/ai-gateways/{id}/models`. A gateway is a **Project** reusing `konnectControlPlaneId` plus `konnectAiGateway: true` (so existing Konnect-project rules apply and CP sync doesn't delete it). Own environment with `proxy_host`. Catalog stored as `Workspace.konnectAiGatewayModels`.
- **Request tree** (`ensureAiGatewayTree`, create-only, keyed `ai:<gatewayId>:...` in `konnectRouteId`): **flat** `Routes and Models` folder, one streaming chat request per route, starter tests on the folder. Create-only so user edits survive re-sync, which also means a changed path/format in Konnect does not propagate and old-shape gateway projects must be removed and re-synced.
- **Models & Pricing tab** (`ai-gateway-models-pane.tsx`, the only collection tab on the gateway project): models grouped by path, price column, **Try now** per route. The Model Evaluator is not offered from this project. Rotating models (several `targets`) get a row per target.
- **Endpoint paths:** hardcoded map (`anthropic` → `/v1/messages`, `openai` → `/chat/completions`, **no `/v1`** for OpenAI-format gateway routes, confirmed live). A `/v1/...` path 404s with "no Route matched".
- **Not mirrored in `inso`.**
- **Gateway 404 debugging:** control request to a known-good route; data-plane `config_sync` via `list_ai_gateway_nodes`; diff the failing model entity against a working one; the gateway's own example cURL.

## 3. Model Evaluator (Oct 6–7, naming Oct 7)

**What:** the collection runner, reached only from the **testing project** (named **Model Evaluator** in tab, breadcrumb, button, context menu; regular collections keep "Runner"). One **Evaluate** tab: Requests, Skills, Models, Judge, in that order.

- **Selection:** requests none-by-default, models all-by-default; picks live in the runner context (`RunnerState.selectedModelIds` / `selectedSkillIds`, survive tab switches, reset when the runner tab closes); more than 20 runs asks first. Copy is deliberately short ("Select at least one prompt, which will run for each selected model. Optionally, select skills to include for each run.").
- **Fan-out:** requests × models become runner rows; `sendActionImplementation({ aiGatewayModelId, aiSkillIds })` retargets the request **in memory only** via `applyAiGatewayModelOverride` (route path swapped, body `model` = route value, `stream: false`). It skips only when the URL matches no catalog route or the body isn't a chat request.
- **No format opinion:** a request/model format mismatch is never skipped; if the gateway rejects it, the row gets an amber "declined by gateway" note and its tests are dropped. The URL suffix is not rewritten.
- **Results:** `<h2>` per iteration, `<h3>` per model (alias, actual model, route, tokens, cost), requests under each; ranked summary table at the top (Route, Model, Score, then tokens, cost and tests passed; a Judge checks column appears when any model has judge results) with chips for "declined" and "rotating"; clicking a model jumps to its section; each result's request name links to its response (`requestId`/`responseId` on results).
- **Rotating aliases:** one checkbox with "rotates between N models"; the summary splits into a row per model that answered; nothing can force which target answers.
- **Model identity:** group/summarize/anchor by **route + alias**, never the model string (it becomes a dated id once a response arrives).
- **Tokens:** read from the plain JSON response (`withUsageFromResponseBody`). `getResponseBodyBuffer` returns a `Uint8Array` over IPC, so use `bodyBufferToUtf8`, not `.toString()`.
- **Starter tests** pre-installed on the Routes and Models folder (valid response, under 500 tokens).
- **Open:** not mirrored in `inso`; no Playwright coverage of the runner comparison; header strip says `Tokens:` while headings say `Total Tokens:`; Test % counts tests only (an always-erroring model shows "—", not 0%).

## 6. Judge (Oct 7, extended Oct 16)

**What:** `insomnia.judge(criteria, options?)` lets a second model grade the current response in an after-response script; results feed ordinary tests.

- **Helper** (`insomnia-scripting-environment/src/objects/judge.ts`): returns `{ checks, passed, total, score, allPassed, reason, summary, raw }`. Each criterion scores **0, 0.5 or 1**; **runs per judgment** (1–10, parallel, averaged) smooths a noisy judge; pass stays strict (average exactly 1) while partial credit goes into `score`. `summary` shows every run and reason ("work in public"). `verdict.expectAllPassed(); return verdict;` records the checks on the test result (`RequestTestResult.checks`); a test may also return a string shown as `detail`.
- **Controls** (`insomnia.judge(criteria, { answer })`) have `control: true` and are excluded from a model's numbers.
- **What the judge sees (Oct 16):** criteria, the answer, the question (last user message), and the **instructions the model was given** (the request's system prompt, which already includes any skills, since they are applied at send time), plus the Judge tab's extra instructions. It does not see earlier turns, tokens, cost, timing or other tests. Listed on the Judge tab.
- **Judge tab** (`ai-judge-pane.tsx`, `?collectionTab=judge`): the judge is a **catalog model** (`Workspace.aiJudge.modelId`; an older `requestId` still works until a model is chosen), plus extra instructions (sensible default in `common/ai-judge.ts`) and runs per judgment. `network.ts` `resolveJudgeConfig` builds the request from the model like a starter route request. Judge calls are ordinary gateway traffic, not counted in the cost column.
- **Starter prompt "Judge Demo"** (created with the Prompts folder, so existing testing projects need delete + re-sync): asks "What are the main differences between TCP and UDP?" and has one judge test with four criteria (TCP reliable and connection-oriented, UDP connectionless, an example use of each, organised as a list). Needs a judge chosen on the Judge tab. The three starters have explicit `metaSortKey`s so they keep their order (they are created in the same millisecond).
- **Self-judging is allowed** (decision): the Evaluate tab's Judge section links to the tab and says it isn't best practice; nothing blocks or warns.
- **Open:** judge request auth isn't applied; format (OpenAI vs Anthropic) is guessed from the URL/body; not mirrored in `inso`; the Anthropic-format judge is unit-tested only.
- **Limit (upstream, unchanged):** a single streaming prompt has no Tests tab and runs no after-response scripts, so tests show only in the Model Evaluator. We decided not to build a single-request path; raise with engineering.

## 7. Model Scoring (Oct 7)

- **Model Scoring tab** (`ai-scoring-pane.tsx`, `?collectionTab=scoring`): an editable script (real code editor with JSHint) saved to `Workspace.aiScoring.script`; absent means the default; saving text equal to the default clears the setting.
- **Default** (`common/ai-scoring.ts`): `0.7 × testsScoreRate + 0.3 × (cheapestCost / modelCost)`; each test counts 1 if passed, 0 if not, except a judge test counts its share of checks passed. Unpriced models get 0 for the cost part. Each score carries a `note` shown on hover.
- **Runtime:** at the end of a run (`debug.runner.tsx` `clientAction`) per-model totals go to the script as `models`; it returns `[{ id, score, note? }]`. Failures never block a run (`scoringError` + amber banner). Scores are saved with the run (`modelScores`), frozen like cost; the table ranks by score.
- **Open:** how much judge checks should count in the default formula; per-request scoring; scoring log files (`scoring_<workspaceId>`) are never cleaned up; unverified under the QuickJS sandbox mode.

## 11. Auto-convert LLM URLs to SSE Requests (Nov 4)

**What:** the discoverability answer for a developer who has only a URL (comfortable with AI Gateway, OpenAI or Anthropic, doesn't know Konnect or that Insomnia helps). A blank URL that becomes one ending in `/chat/completions` (OpenAI) or `/v1/messages` (Anthropic) is converted to a streaming chat request, so the existing chat UI, SSE view and token/cost summary just work. Same experience as pasting a cURL, but from a bare URL.

- **Trigger (one rule, deliberately boring):** the URL goes from **blank** to a match. Never on typing (the last-seen value is held in a ref, not `activeRequest.url`, which lags the async patch), never on editing a filled URL, never re-triggered after Undo. Verb history is ignored. Path-suffix match only (query, fragment, trailing slash, case ignored; plain string handling so `{{ _.base }}/chat/completions` matches). Not covered: OpenAI `/v1/responses` (body uses `input`, not `messages`) and Gemini (streams via a different URL suffix).
- **What it sets** (`common/llm-url.ts`, unit-tested): POST, `Accept: text/event-stream`, `Content-Type`, body with `"stream": true` merged into any existing JSON (OpenAI also gets `stream_options.include_usage`, Anthropic gets `max_tokens`). **`model` is left empty on purpose**: a URL can't tell us, and a wrong default is worse.
- **Entry points:** URL bar (`request-url-bar.tsx` `onChange`), cURL paste and the sidebar/folder "From Curl" menus (`debug.request.new.tsx`), and file/URL/Postman imports (`common/import.ts`, the two `services.request.create` sites). Imports use `autoConvertImportedRequest`, which also leaves a request alone if its body is non-empty and not a JSON object.
- **Setting:** `autoConvertLlmUrls`, default on, Preferences > General, "Auto-convert LLM URLs to SSE Requests". Read once per import via `services.settings.get()`.
- **Feedback:** a small non-modal popover under Send/Connect (`llm-url-converted-popover.tsx`, React Aria `Popover` with `triggerRef`), auto-hides after 5s, hover pauses it. It offers Undo and a link to Preferences, and tells the user to add a `model` on the Body tab. Imports show no popover.
- **The missing-model failure:** a blank `model` through Kong AI Gateway gives a 503 `name resolution failed` (routes are chosen by matching the body `model`; the gateway has no `/models` listing). We don't block Connect. Instead an auto-converted request with a 400+ response and no `model` shows a red line under the status: "This looks like an LLM request with no 'model' specified in the body." Direct to OpenAI/Anthropic an empty model would also be rejected (not tested; no keys), just with a clearer message.
- **Not done / ideas:** Konnect nudge from Kong response headers (`Server: kong/...-ai-gateway`) with a link to sync the gateway; key the red note on URL + missing model instead of the session marker; pre-fill `model` inside a synced gateway project; a model input on streaming requests (before the first connect the only place is the raw Body tab); a smoke test for the paste flow.
- **Future idea (Cam, 2026-11-04): a way to tease that AI Gateway exists** for people who never hit a Kong URL. Not designed yet; the Kong response-header nudge above is one candidate, an in-app teaser for people with no gateway is another.
- **Verified:** 30 unit tests (`llm-url.test.ts`), type-check and ESLint on changed files; click-tested by Cam (paste, popover, Undo, 503 note, and the cURL and import paths; "tested enough" 2026-11-04).

## 12. Konnect Plugin insights on the response (Nov 4; extends piece A)

**What:** make the guts of what plugins do discoverable where the developer is already looking: the response. Two pieces, both driven by one registry. Authored on this branch only (not on `3593`).

- **Registry** (`common/konnect-plugin-headers.ts`, unit-tested): one entry per plugin with a header-name matcher, an optional companion matcher (e.g. `Retry-After`, claimed only when the plugin's own headers are present), a `summarize()` that returns ONE short line (or null), and the label/plugin names. `groupPluginHeaders(headers, attachedPluginNames)` returns `{ groups, otherHeaders }`. **To support a plugin, add one entry; no UI changes.** Currently one entry: `rate-limiting` + `rate-limiting-advanced` (same header names: `X-RateLimit-Remaining-<window>`, `RateLimit-*`, `Retry-After`; windows are names for rate-limiting and seconds for advanced). ## Gotchas worth keeping (reusable beyond this branch)

- **Data layer prunes undeclared top-level fields silently** (`init-model`): a new model field must be in `init()` defaults or `optionalKeys`, and the Electron **main process must be restarted** (the renderer hot-reloads, main does not). Nested fields are not pruned. Symptom of forgetting: the field vanishes on save, duplicate projects appear. Always add a save-and-read-back test.
- NeDB `{ $ne: null }` also matches documents where the key is absent; post-filter in JS.
- Environments: the JSON editor writes `data` only, the table editor writes `data` and `kvPairData`; treat `data` as authoritative.
- `deleteStaleRequests` (CP sync) deletes user-added requests; never reuse it for user-authored content.
- Konnect AI Gateway is a separate resource from a control plane (`list_control_planes` won't list it; use `list_ai_gateways` etc.). Updating a model via the API needs the full body plus `type`, and policies **by name**.
- Folder-level after-response scripts concatenate down to every request beneath them; collection-level scripts don't exist.
- `CodeEditor` is intentionally uncontrolled (a body changed from outside needs a remount to refresh); don't "fix" it per feature.
- A realtime follow-up reconnect creates a new `response` row; state keyed on `response._id` needs a way to tell a self-caused reconnect apart (`skipNextChatSeedRef`).
- Overlays (toasts, popovers, react-aria portals) render outside the pane's DOM: scope smoke-test locators to `page`. A toast region once blocked clicks; the fix is `pointer-events-none` on the region with `pointer-events-auto` on each card.
- Global hotkeys bind in the capture phase on `window`, so a child can't `stopPropagation`; use `data-ignore-send-hotkey` and check it in the global handler.
- Compose/editor UI must be verified by typing several characters into a freshly created field while a response is on screen; two bugs shipped because checks were done one action at a time.
- Moving JSX by script: never find a block's end by a bare `)}` match (nested everything once; `tsc` didn't notice). Use a real edit with a unique anchor.
- macOS: a stray process on `127.0.0.1:<port>` beats Docker's `0.0.0.0:<port>` publish silently (`lsof -nP -iTCP:<port> -sTCP:LISTEN`).
- The dev app's data is `~/Library/Application Support/insomnia-app/*.db` (the `Insomnia/` sibling is the packaged app); append-only JSON lines, read-only while it runs. Dev builds ignore `--user-data-dir`.
- Native `title` tooltips don't show in the desktop app; use the app's `Tooltip` (`followCursor` when wrapping a full-width row).
- zsh doesn't word-split an unquoted `$var`; run ESLint per package; Prettier `--write` on a file that wasn't clean reformats unrelated lines (check `git diff`).
- **`.pane` is a two-row CSS grid** (`grid-template-rows: var(--line-height-sm) minmax(0, 1fr)` in `main.css`): a header row, then ONE body row. Any extra direct child of `Pane` becomes the `1fr` body row and stretches to fill it (a one-line note once took "several inches"; a banner did the same). Put new rows inside the body (e.g. as the first child of the `Tabs` flex column), or use a portaled popover.
- **Uncontrolled editors + async patches:** `patchRequest` saves asynchronously. To change a request from code and have the Body/Headers editors show it, `await services.request.update(request, patch)`, then `patchRequest(...)`, and only then remount the editors (the pane's `uniqueKey` includes an `editorNonce`). Remounting first brings them back with the old values. The method dropdown is controlled, so it can look half-applied.
- Moving a big JSX block by script and re-indenting it turns a 15-line change into a 500-line diff; prefer a different anchor (an existing flex column) over wrapping.
- ESLint `--fix` rewrites `fn(undefined)` to `fn()`; if the parameter is required that breaks type-check. Make the parameter optional or pass `null`.
- Hand scripts to the user as a file or clipboard (`! pbcopy < file`), never terminal copy-paste (it injects spaces into wrapped lines).
