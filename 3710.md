# 3710 — Undo hint pointing at Response History

## Goal
Selecting an older response in Response History restores the whole request + response, which is effectively a coarse undo. When the user presses undo, show a subtle, auto-dismissing hint pointing at it.

## Behavior
- Any Undo (Edit menu / Cmd+Z) shows a small note under the response-history button (top right of the response pane).
- Copy: "Undoing? You can back up to any prior Request/Response here." Styling is the original subtle look (bordered `--color-bg` box, `--hl` text). `--color-surprise` and an inverted `--color-font` bg were both tried and judged far too loud; a design tweak is left to the owning engineer.
- "Don't show again" link persists the new `hideUndoResponseHistoryHint` setting (also a checkbox in Preferences > General so it can be re-enabled).
- Keyboard Cmd/Ctrl+Z also triggers it: macOS via the Edit-menu accelerator; a capture `keydown` listener in `renderer-listeners.ts` covers Win/Linux where CodeMirror handles Ctrl+Z before the menu.
- Disappears after 5s (repeat undos restart the timer). It is clickable now (for the link), so it can intercept clicks on the tab bar's right edge while visible.
- Only shown when there is an older response to go back to (`responses.length > 1`).
- Redo does not trigger it.

## Implementation
- `editor-undo.ts`: `dispatchEditorUndo('undo')` dispatches a `window` CustomEvent (`UNDO_PERFORMED_EVENT`). That function is the single app-level undo path, so one hook covers CodeMirror and native inputs.
- `response-history-dropdown.tsx`: listens for the event, owns the hint state/timer, renders the bubble absolutely positioned in the (relative) `PaneHeader`. The Dropdown is now wrapped in a fragment, so the diff is mostly re-indentation.

## Notes / possible follow-ups
- Bubble overlays the right edge of the response tab bar (normally empty).
- Not shown for requests with no response pane (nothing to restore).
- No tests added (UI timing hint); needs a click-test.
