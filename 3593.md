# 3593 — Plugins tab for Konnect-linked requests

## Goal

Insomnia's unique advantage is its Kong Konnect integration. Add a **Plugins** tab to the request pane that shows, for a request imported/synced from Konnect, the Kong plugins applied to its route (and inherited from its service/control plane) in execution order. Readonly. Links out to plugin docs and to editing the plugin in Konnect. Includes a "decK command" modal per plugin, and suggests a few common plugins not currently applied.

A **Debugger** tab (Kong debugger / latency breakdown) was also discussed but is explicitly **out of scope for this task** — will be scoped separately once we get to it.

## Scope

- New `Tab id="plugins"` / `TabPanel` in `packages/insomnia/src/ui/components/panes/request-pane.tsx`, following the existing Params/Body/Auth/Headers/Scripts/Docs pattern.
- **Visibility:** tab only renders (or shows real content) when the request is Konnect-linked, resolved via the existing chain:
  `Request.konnectRouteKey` → `Workspace.konnectServiceId` (via `Request.parentId` ancestry) → `Project.konnectControlPlaneId` (via `Workspace.parentId`).
  If any link in that chain is missing, show an empty/"not connected to Konnect" state instead of the tab content.
- **Data (real Konnect API, via `packages/insomnia/src/konnect/api.ts`):**
  - New fetcher(s) added to `api.ts` wrapping the Konnect Control Planes Configuration API:
    - `list_plugin_with_route` (RouteId + controlPlaneId) → plugins directly on the route, in order.
    - `list_plugin` (controlPlaneId, optionally filtered) → all plugins in the control plane, used to (a) show service/global-level plugins that also apply, and (b) compute "common plugins not yet applied" suggestions.
    - `fetch_plugin_schema` (pluginName + controlPlaneId) → used for suggestion metadata / config shape shown in the decK modal.
  - Execution order: Kong applies plugin phases in a fixed priority order per plugin type, then route-scoped before service-scoped before global. For this prototype we sort by Kong's documented plugin priority metadata where available, else the order returned by the API — **not a fully authoritative resolution of Kong's real phase-based execution order** (flagged as a shortcut below).
- **Row content per plugin:** name, enabled/disabled state, scope badge (route/service/global), link to `https://developer.konghq.com/plugins/<name>/` docs, link to edit the plugin in the Konnect UI (deep link using controlPlaneId + plugin id), and a "decK command" button.
- **decK command modal:** clicking a plugin's decK button opens a modal with a copyable `deck` CLI snippet representing that plugin's config (e.g. a `deck gateway apply`-style snippet built from the plugin's JSON). This is **illustrative, not a real decK-validated command** (shortcut, flagged below).
- **Suggested plugins:** below the applied-plugins list, show 3–5 common/popular plugins (e.g. rate-limiting, key-auth, cors, request-transformer, prometheus) that are not already applied to this route, each with a docs link and an "Add in Konnect" link. Suggestion list is a static curated list for this prototype, not personalized/algorithmic.

## Known shortcuts / not production-ready

- Plugin execution-order sort is a best-effort approximation, not Kong's real phase-based resolution — flagged inline where implemented.
- decK command modal shows a fabricated illustrative snippet (not real `deck` CLI output/validated command), though the control-plane name it references is real (`Project.name`, kept in sync with `controlPlane.name`).
- Suggested-plugins list is a static hardcoded list, not derived from usage analytics or control-plane context.
- No new persisted schema — reusing existing `konnectRouteKey` / `konnectServiceId` / `konnectControlPlaneId` fields already on `Request`/`Workspace`/`Project`.
- Debugger tab is intentionally excluded from this task.

  1. `konnectRouteKey` is a composite key (`${route.id}:${method}:${pathSegment}:${protocol}`, see `konnect/sync.ts`), not a raw route UUID. `resolveKonnectRouteLink` now splits on `:` to extract the actual route id before calling the plugins API.
  2. `/routes/{id}/plugins` only returns plugins attached directly to the route — it misses service-scoped and global-scoped plugins that still apply to that route's traffic (e.g. a global rate-limiting plugin wasn't showing as "applied," and was incorrectly appearing under "Suggested"). `useKonnectPlugins` now merges direct route plugins with service-scoped (matching this route's service) and global-scoped (no route/service/consumer) plugins from the full control-plane plugin list.
