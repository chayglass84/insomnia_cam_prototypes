# 4348 — MCP debugger (port of Ardi into Insomnia)

Prototype. Replaces most of Insomnia's current MCP client with a port of Ardi
(`kong-insomnia/ai-debugger`, live at https://ai-debugger-dev.web.app/). Branch `4348`, cut from
`upstream/develop` @ 911271895 (the fork's `origin/develop` was 145 commits stale on 2026-11-19).

## Goals (in priority order)

1. **Edit and replay from anywhere.** Edit and re-send any request in the trace, not only terminal responses.
2. **Full MCP 2026-07-28 support**, plus the older protocol versions, selectable per request.
3. **Step-by-step OAuth debugging.** XAA/JAG/EMA live in the later "even more auth" slice (S8).

Scope is MCP servers only. Chat/model playground, evals and A2A belong to 3593AI or are out of scope.

## Decisions (agreed with Cameron, 2026-11-19)

- Replace the existing MCP client. Port Ardi's protocol/transport/trace layers rather than rewrite.
- The Electron main process does the networking. No hosted proxy and no relay (CORS and stdio are native).
- **Version-adaptive UI.** One shell, driven by a per-version profile (see below).
- Mocks are fine, but every one must be visible in the UX and in the code (see "Marking mocks").
- No DB migrations. New per-request fields are optional on `McpRequest` (NeDB is schemaless).

## Version-adaptive UI

`ProtocolProfile` per protocol version: `{ version, era: 'session' | 'stateless', tabs, traceEventKinds, builderFields }`.

- **Auto** (default): probe `server/discover`, fall back to the `initialize` handshake, and show what was chosen.
- **2026-07-28 profile:**
  - Tabs: Tools, Resources, Prompts, Tasks, Subscriptions.
  - Request builder shows `_meta`, `Mcp-Method`/`Mcp-Name` and cache hints.
  - Elicitation is MRTR.
  - No sampling, roots, logging, ping, session id or handshake.
- **Legacy profiles** (2025-11-25, 2025-06-18, 2025-03-26, 2024-11-05):
  - Add the tabs and trace events that exist only there: Roots, Sampling, Logging, Ping, session id, handshake, SSE resume.
  - The old HTTP+SSE transport is available for 2024-11-05.
- The switch is a profile swap, not two apps. The trace, replay and diff are shared.
- **Replay a call under another version and diff the two** (cheap, since the replay engine is shared).
- Open: legacy server-initiated sampling and roots forms. Reuse the current Insomnia components if they wire up cheaply, else mock (S3).

## Ardi source map (what to port)

- `web/frontend/src/protocol/` is the Protocol and Transport interfaces. `mcp/MCPHTTPProtocol.ts` covers 2024-11-05 to 2026-07-28. Also `era.ts`, `elicitation.ts`, `tasks/`, `negotiate/`, `wire/`.
- `stores/useTraceStore`, `useCapabilityStore`, `useReplayStore`, `useCompareStore`, `taskPoller`.
- `components/trace/` is the trace UI, `EditReplayButton`, `CompareView`, `continueFromRun`, `InputRequiredDetail`, `TaskDetail`.
- `lib/oauth/` and `lib/oauth/steppedFlow/` are the OAuth engine and explainers.
- `protocol/mcp/clientCodeGenerator.ts` is copy-as-code.
- `e2e/` has the tasks mock server fixture, reusable for tests.
- Ardi is React 19, Zustand, shadcn and Tailwind. Re-skin to React Aria and Insomnia's Tailwind. Use Router loaders and NeDB, not Zustand (per AGENTS.md).

## Current Insomnia MCP (to replace)

`main/network/mcp.ts`, `main/mcp/*` (SDK client, transports, OAuth provider), `ui/components/mcp/*`, and `insomnia-data` `mcp-request`, `mcp-payload` and `mcp-response`.

- Keep the models and the workspace, request and environment concepts, so sync, git, vault and env vars keep working.
- Add `protocolVersion` (optional) to `McpRequest`.
- History keeps using the per-connection JSONL event log.

### S2 exact replay (built 2026-11-19, uncommitted)

- **Edit & replay now sends the request exactly as written**, including its `_meta` and its HTTP headers. The editor is prefilled with `{method, params, headers}` as they went on the wire (credential headers show as `<redacted>` in the trace; on send, any header still equal to the marker is restored by name from the connection's live auth headers, and deleting a header sends without it, which is how you test a 401).
- To make that honest, the trace's request row now records the params as actually sent (stateless calls show the injected `_meta`: protocol version, client info, capabilities) instead of the pre-injection params. The request diff compares `{method, params, headers}`.
- In-call failures (not just connect) now put the HTTP status, response headers and a truncated body in the error row.
- Implementation: `MCPInvocation.exact` in `capabilities/methods.ts`, `prepareCall` in `MCPHTTPProtocol.ts`, `exactHeaders` on `mcpDebugger.invokeRaw`.
- Limits: `Content-Type` and `Accept` are still added by the transport; a legacy replay after a reconnect carries the old `Mcp-Session-Id` (the server will reject it, which is accurate but may surprise); params are replayed as JSON text, so non-JSON values can't be expressed.

## Known shortcuts / not production-ready

- `ProtocolProfile.tabs`/`traceEventKinds`/`builderFields` are the *intended* UI per version, rendered only as a preview in S0 (`profiles.ts`, `mcp-debugger-panel.tsx`).
- `probe.ts` is unauthenticated plain `fetch`: no custom headers, TLS options or HTTP+SSE fallback. Replaced by the ported `MCPHTTPProtocol` in S1.
- The Debugger tab is a scaffold that S1 replaces. The version picker moves into the URL bar.
- `tsc` baseline is already red on this branch (34 errors, grpc/zod) because `node_modules` predates `upstream/develop`; S0 adds none. Run `npm ci` before launching the app.
- S1: sessions and traces are in-memory only (`service.ts`), lost on restart. S2 adds persistence for runs.
- S1: the renderer polls state and trace every 500 ms (`use-mcp-debugger.ts`) instead of subscribing to pushed events.
- S1: direct `fetch` with no TLS options (`sslValidation`), cookies, proxy settings, client certs or user-agent toggle. Insomnia's existing network features are not wired in.
- S1: Auth tab keeps Insomnia's OAuth 2 (`getOAuth2Token`) and drops the legacy MCP auth-flow option; the stepped MCP OAuth debugger is S5.
- S1: params are kept per capability in component state (not stored in `McpPayload`). Resource templates are not listed (Ardi's registry has no template type).
- S1: sessions are not closed on app quit (`closeAllMcpDebuggerSessions` is exported but not wired).
- S1: the old MCP client (`main/network/mcp.ts`, `main/mcp/*`, legacy UI) is still present for stdio requests and unused by HTTP.
- S1: the ported Ardi files in `common/mcp-debugger/protocol/` are intentionally not reformatted to Insomnia's lint rules (about 75 eslint errors, mostly style) so they stay diffable against Ardi. `classify.ts` was edited: the browser-only "cors" guess is replaced by the real network cause.
- Gotcha fixed in S1: `McpRequest.protocolVersion` must be in the model's `optionalKeys` (`insomnia-data/src/models/mcp-request.ts`), otherwise `initModel` prunes it on every save and the version picker silently does nothing. S0 added only the zod field.

## Glossary: "even more auth" (for S8)

- **XAA (Cross App Access)** is enterprise-managed auth. The user signs in once to the company IdP. The client, not the user, gets access to each MCP server, and the admin controls which apps may reach which servers. No per-server consent popup.
- **ID-JAG (Identity Assertion JWT Authorization Grant)** is the token at the center of XAA. The client trades the user's IdP ID token for an ID-JAG aimed at one specific MCP server's auth server (RFC 8693 token exchange).
- **JWT bearer grant (RFC 7523).** The client presents the ID-JAG to the MCP server's auth server and gets back an ordinary access token.
- **EMA (Enterprise-Managed Authorization)** is MCP's official extension that standardizes this flow. XAA is the vendor-neutral name for the same idea. The debugger should show each hop (IdP login, token exchange, JWT bearer) with decoded tokens.
- **CIMD (Client ID Metadata Documents)** is the client_id as an HTTPS URL pointing to a metadata document. It replaces DCR. This sits in S5, not S8.
